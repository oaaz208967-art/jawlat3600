# جولات 360 — دليل الرفع على Vercel

المحتوى: موقع ثابت (`site/`) + دوال صغيرة للـ SEO (`api/`) + قاعدة بيانات وحسابات على **Supabase** (مجاني للبداية).
لا تحتاج أي أدوات برمجة على جهازك: كل الخطوات من المتصفح.

الوقت التقريبي: 30–40 دقيقة.

---

## 1) إنشاء مشروع Supabase (قاعدة البيانات وتسجيل الدخول)

1. ادخل https://supabase.com وأنشئ حسابًا ثم **New project**. اختر اسمًا وكلمة مرور قوية للقاعدة، واختر أقرب منطقة (مثل Frankfurt أو Bahrain إن توفرت).
2. من القائمة اليسرى: **SQL Editor → New query**، افتح الملف `backend/supabase.sql` من هذه الحزمة، انسخ كل محتواه والصقه واضغط **Run**. يجب أن تظهر رسالة نجاح بلا أخطاء.
3. من **Connect** انسخ عنوان المشروع، ومن **Project Settings → API Keys** انسخ المفتاح العام القديم:
   - **Project URL** (مثل `https://abcd1234.supabase.co`)
   - **Legacy anon public key** (مفتاح طويل يبدأ بـ `eyJ`)
   > مفتاح `anon` عام بطبيعته ويظهر في الموقع، والحماية الفعلية في سياسات RLS التي أنشأها ملف SQL.
   > هذه النسخة لا تدعم مفتاح `sb_publishable_` الجديد في كل الطلبات؛ يلزم تحديث ربط Supabase قبل الانتقال إليه. مفاتيح `anon` القديمة في طريقها للإيقاف.
   > **لا تضع أبدًا مفتاح `service_role` في الموقع أو في GitHub.**

### إعداد تسجيل الدخول (مهم)
الموقع يستخدم **البريد + كلمة المرور** عبر Supabase Auth:

1. **Authentication → Providers → Email**: أبقِ **Confirm email مفعّلًا** (شرط أمان: لا يُمنح المالك صلاحية إلا ببريد مؤكَّد).
2. (اختياري) خصّص قوالب **Confirm signup** و**Reset password** بالعربية.
3. **Authentication → URL Configuration**: ضع في **Site URL** عنوان موقعك (تعرفه في الخطوة 4، ويمكنك تعديله لاحقًا).
4. **بريد حقيقي للإرسال:** خدمة Supabase المجانية المدمجة تسمح بعدد قليل جدًا من الرسائل في الساعة. قبل الإطلاق اربط مزود SMTP (مثل Resend أو Brevo أو SendGrid): **Authentication → Emails → SMTP Settings**.

## 2) تعبئة ملف الإعدادات

افتح `site/assets/config.js` وعدّل القيم فقط:

```js
window.JW_CONFIG = {
  supabaseUrl: 'https://abcd1234.supabase.co',
  supabaseAnonKey: 'eyJ...',
  siteUrl: '',            // نملؤه بعد معرفة الرابط (الخطوة 4)
  allowIndexing: false    // يبقى false حتى استبدال البيانات التجريبية
};
```

---

## 3) رفع المشروع إلى GitHub

1. أنشئ حسابًا على https://github.com ثم **New repository** (اجعله **Private**).
2. اضغط **uploading an existing file** وارفع **محتويات** المجلد `jawlat360` (يجب أن يظهر `vercel.json` و`site` و`api` في جذر المستودع، وليس داخل مجلد إضافي).
3. اضغط **Commit changes**.

## 4) النشر على Vercel

1. ادخل https://vercel.com وسجّل بحساب GitHub، ثم **Add New → Project** واختر المستودع.
2. الإعدادات:
   - **Framework Preset:** `Other`
   - **Build Command:** اتركه فارغًا
   - **Output Directory:** اتركه كما هو (يقرؤه من `vercel.json`)
3. افتح **Environment Variables** وأضف:

   | الاسم | القيمة |
   |---|---|
   | `SUPABASE_URL` | نفس Project URL |
   | `SUPABASE_ANON_KEY` | نفس anon key |
   | `SITE_URL` | رابط موقعك بدون `/` في النهاية |
   | `ALLOW_INDEXING` | `0` |

4. اضغط **Deploy**. بعد دقيقة تحصل على رابط مثل `https://jawlat360.vercel.app`.
5. ضع هذا الرابط في:
   - `siteUrl` داخل `site/assets/config.js` (عدّل الملف من GitHub مباشرة ثم Commit، وسيعيد Vercel النشر تلقائيًا)
   - `SITE_URL` في Vercel
   - **Site URL** في Supabase (الخطوة 1)

> بدلاً من GitHub يمكنك استخدام Vercel CLI: `npm i -g vercel` ثم `vercel --prod` داخل المجلد.

---

## 5) حساب المالك (المدير الوحيد)

لوحة المالك ومدير الجولات مقصورتان على بريد واحد: `o.a.a.z.900@gmail.com`. التحقق في قاعدة البيانات (RLS + دوال SQL) وليس بإخفاء الواجهة فقط.

1. افتح موقعك ← **دخول** ← تبويب **إنشاء حساب** بهذا البريد وكلمة مرور تختارها أنت (لا تُكتب في أي ملف أو ZIP).
2. أكّد البريد من الرسالة، ثم سجّل الدخول: تُمنح صلاحية المالك تلقائيًا (`claim_owner`) ويُحوَّل إلى `/account`.
3. أي حساب آخر، حتى لو مسجّل ومؤكَّد، يُرفض في `/admin` و`/account` (لوحة المالك) وفي كل كتابة على قاعدة البيانات.

## 5-ب) نظام الحجز المباشر

- المالك يفعّل الحجز لكل منشأة من `/account` ← «إعدادات الحجز لكل منشأة» (النوع، طريقة التسعير والسعر، الحد الأدنى والأعلى، المواعيد، فوري أو بموافقة، واتساب، سياسة الإلغاء، حقول إضافية). لا يظهر «احجز الآن» إلا للمنشآت المفعَّلة.
- العميل يسجّل (الاسم، البريد، الجوال، كلمة المرور) ثم يحجز؛ السعر والحالة يحسبهما الخادم (`create_booking`) ولا يستطيع العميل تغييرهما.
- **التحقق من الجوال تجريبي محلي:** الرمز يولّده الخادم ويُعرض على الشاشة مع تنبيه صريح، ولا يُعدّ الجوال موثّقًا فعليًا. لتفعيل SMS حقيقي اربط مزوّدًا ثم غيّر `otp_mode()` في `supabase.sql` (لم يُختبر أي مزوّد).
- لا يوجد دفع إلكتروني؛ البنية جاهزة لإضافته لاحقًا.
- رقم الواتساب لكل منشأة؛ يختفي الزر إن لم يوجد رقم. نص الرسالة الافتراضي قابل للتعديل (`settings/site.waTemplate`).
- **ترحيل الحجوزات القديمة (اختياري):** نفّذ `backend/migrate-kv-bookings.sql` مرة واحدة؛ لا يحذف شيئًا ويمكن إعادته بأمان.

---

## 6) إضافة جولات Kuula (بدون كود)

1. ارفع جولتك على Kuula وانسخ رابطها أو كود التضمين.
2. من `/admin` اختر المنشأة، الصق الرابط أو الكود، اضغط **تحليل** ثم **حفظ**، واستخدم **اختبار** لمعاينتها.
3. المسموح فقط: `kuula.co` و`my.matterport.com` (قائمة بيضاء في الموقع وفي سياسة CSP).

لا تحتاج حساب Kuula داخل الموقع نفسه؛ يكفي رابط الجولة.

---

## 7) نطاق خاص (Domain)

1. Vercel → **Settings → Domains → Add** وأدخل نطاقك واتبع تعليمات الـ DNS.
2. حدّث `siteUrl` و`SITE_URL` و**Site URL** في Supabase إلى النطاق الجديد.
3. من `/admin` حدّث **رابط QR الأساسي** ليطابق النطاق قبل طباعة أي QR.

---

## 8) الإطلاق الحقيقي وفهرسة جوجل

الموقع يأتي **مغلقًا أمام الفهرسة** لأن البيانات الأولية «تجريبية».

عند الجاهزية (بعد استبدال البيانات التجريبية ببيانات حقيقية):
1. `allowIndexing: true` في `config.js`.
2. `ALLOW_INDEXING=1` في Vercel ثم **Redeploy**.
3. سجّل الموقع في Google Search Console وأرسل `https://نطاقك/sitemap.xml`.

الصفحات التجريبية والخاصة (`/admin` و`/account` و`/go`) تبقى `noindex` دائمًا.

## قائمة فحص بعد النشر

- [ ] الصفحة الرئيسية تفتح، والبحث والخريطة والفلاتر تعمل
- [ ] تسجيل الدخول بالبريد وكلمة المرور يعمل، وحساب غير المالك يُرفض في `/admin`
- [ ] بعد دخولك كمالك: `/admin` و`/account` تعرضان الأدوات
- [ ] فعّل الحجز لمنشأة، واحجز بحساب عميل، ثم أكّد الطلب كمالك وتحقق من «حجوزاتي»
- [ ] حساب مالك تجريبي: أضف منشأة ← تظهر عندك في المراجعة ← اعتمدها ← تظهر لزائر غير مسجل
- [ ] جولة Kuula تفتح داخل الصفحة
- [ ] `/robots.txt` يعرض `Disallow: /` (قبل الإطلاق) و`/sitemap.xml` يفتح
- [ ] شارك رابط صفحة منشأة في واتساب: تظهر معاينة بالاسم
- [ ] افتح الموقع من الجوال وجرّب الحجز والتقييم

## ما الذي يحميه الموقع

- **سياسات RLS** في Supabase: الزائر يقرأ العام فقط؛ المستخدم يكتب في مساراته فقط؛ المنشآت لا تُنشر إلا بيد المدير؛ الحملات والمراجعات الخاصة للمدير فقط.
- **CSP صارمة:** سكربتات من نطاقك فقط، وإطارات من Kuula وMatterport فقط، واتصال بنطاقك وSupabase فقط.
- HSTS، منع التضمين (`frame-ancestors`)، `nosniff`، سياسة أذونات.
- كل نص يُدخله المستخدم يمرّ عبر تهريب HTML، ويُتحقق من نطاقات الجولات قبل العرض.
- لا يوجد أي سر في الكود.

## حدود معروفة في هذه النسخة

- **لا دفع إلكتروني:** الحجز طلب يؤكده المدير. ربط بوابة دفع يحتاج واجهة جديدة خلف `Payment` في الكود.
- **تزامن حجوزات الإقامة:** قد يتأكد حجزان متداخلان عند وصولهما في الوقت نفسه؛ يلزم معالجة التزامن في قاعدة البيانات قبل تفعيل الحجوزات الحقيقية.
- **استعادة كلمة المرور:** إرسال رابط الاستعادة موجود، لكن إتمام تغيير كلمة المرور يحتاج تطويرًا واختبارًا قبل الاعتماد عليه.
- **لا رفع صور:** الصور حاليًا بدون رفع من المالك (يُضاف لاحقًا عبر Supabase Storage).
- **التحليلات** تُسجَّل فقط من حسابات مسجّلة الدخول، وهي عيّنة وليست بديلًا عن Google Analytics.
- التحديث الحي للبيانات كل ~8 ثوانٍ (استعلام خفيف)، وليس لحظيًا.
- العمولة والأسعار أرقام عرض إدارية؛ لا يوجد محاسبة تلقائية. وإجمالي الحجوزات ليس إيرادًا.
- لم يُختبر هنا النشر الفعلي على Vercel/Supabase الحقيقيين، فاتبع قائمة الفحص أعلاه بعد الرفع.

## الاختبارات (اختياري، تحتاج Node 24)

```bash
npm i playwright                       # مرة واحدة
tests/pg/up.sh reset && tests/pg/sql-test.sh   # 90 فحص SQL/RLS على PostgreSQL محلي حقيقي (يحتاج PostgreSQL 14+)
tests/pg/up.sh reset && node tests/e2e.js      # متصفح + خادم محاكٍ لـ Vercel + محاكي Supabase فوق PostgreSQL المحلي
node tests/mobile.js                   # فحص الجوال 375px
node tests/crawl.js                    # زحف داخلي
```
> هذه اختبارات محلية؛ لا تثبت عمل Supabase أو Vercel أو مزوّد SMS الحقيقي. جرّبها بنفسك وفق قائمة الفحص أعلاه.

## هيكل الحزمة

```
site/            الموقع (HTML قالب + assets/app.js, style.css, backend.js, config.js)
api/             page.js (SEO ومعاينة المشاركة) · sitemap.js · robots.js
backend/         supabase.sql (الجداول + RLS + دوال الحجز) · migrate-kv-bookings.sql (ترحيل اختياري)
vercel.json      التوجيه ورؤوس الأمان والتخزين المؤقت
tests/           e2e والجوال والزحف · pg/ (اختبار SQL المحلي)
```

## تعديل البيانات لاحقًا

المدن والتصنيفات والأماكن التجريبية في أول `site/assets/app.js` (قسم DATA LAYER). المنشآت الحقيقية تُضاف من حسابات المالكين وتُعتمد من `/admin`، ولا تحتاج تعديل كود.
